# Редакторская приёмка русской сказки

В закрытом пилоте Work передаёт одному штатному агенту авторскую работу, другому — независимое чтение готовой версии. Сохраните черновик в приватном каталоге. Команда принимает результат серверного генератора с полями `title`, `story_text`, `next_hook` либо исходник книги с `title`, `chapters[].title`, `chapters[].paragraphs`. В этом исходнике зацепка может уже находиться в последнем абзаце. Возраст указывайте в поле `age`, когда он известен.

Из корня репозитория создайте карточку рядом с приватной рукописью.

```shell
python -m backend.app.editorial_review draft.json --output review.json
```

Редактор открывает тот же файл, читает его вслух по фразам и заполняет своё имя или роль в `reviewer`. Для каждого критерия нужны `decision` (`pass` или `revise`), `location` (глава и абзац или финал) и `evidence` (конкретное наблюдение, при необходимости точная цитата и предлагаемая правка). В частности, он проверяет, понятно ли, кто отвечает в диалоге, из какого действия вырос поворот и что именно заинтересует ребёнка в следующем приключении после завершения этой истории.

```shell
python -m backend.app.editorial_review draft.json --review review.json
```

Код выхода `0` у проверки означает, что редактор принял текущий текст по всем четырём критериям. `1` возвращает автору отмеченные места. `2` означает ошибку карточки или другую версию рукописи. После правки создавайте карточку новой версии отдельным файлом. Файлы проверки и цитаты конкретной семьи остаются в приватном пространстве. Во внешнем журнале достаточно идентификатора версии, вердикта и следующего шага.

Создание и сверка карточки работают локально без обращений к провайдеру. Изменение одной фразы требует пересборки и проверки текста. Сохранённые иллюстрации используются повторно, если действие и изображённые детали сохранились. Сверка карточки подтверждает запись редактора о прочитанном тексте. Получение оплаты, PDF-проверки и количество иллюстраций сами по себе не подтверждают эту приёмку.
